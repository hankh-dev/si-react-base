# 구조와 동작 방식

## 1. 레이어

```
app  →  pages  →  features  →  shared
```

| 레이어     | 담는 것                                                    | 예                                       |
| ---------- | ---------------------------------------------------------- | ---------------------------------------- |
| `app`      | 앱에 하나뿐인 것: 진입 구성, 라우터, 화면 등록부, 레이아웃 | `router.tsx`, `screens.ts`, `MainLayout` |
| `pages`    | 화면. 한 화면 = 탭 하나                                    | `UserListPage`, `UserFormModal`          |
| `features` | 업무 영역별 API 호출, 조회 훅, 타입, 검증 규칙             | `features/user/api.ts`, `queries.ts`     |
| `shared`   | 업무와 무관하게 어디서나 쓰는 것                           | `http`, `DataGrid`, `formatDate`         |

규칙은 두 가지이고 ESLint 가 검사합니다 (`eslint.config.js`).

1. **아래 방향으로만 import 합니다.** `shared` 는 `features` 를, `features` 는 `pages` 를 모릅니다.
2. **외부 제품은 감싼 것을 씁니다.** 화면과 `features` 는 `axios`, `ag-grid-*` 를 직접 import 하지 않고
   `shared/api` 의 `http`, `shared/ui` 의 `DataGrid` 를 씁니다. 고객사 표준 그리드로 바꾸거나 공통 응답 규격이
   달라져도 고칠 곳이 `shared` 안쪽으로 한정됩니다.

다른 레이어는 항상 `@/` 별칭으로 import 합니다 (`@/shared/ui/Modal`). 같은 폴더 안에서만 상대 경로를 씁니다.

## 2. 상태는 어디에 두는가

| 상태                                         | 위치                                     | 이유                                                |
| -------------------------------------------- | ---------------------------------------- | --------------------------------------------------- |
| 서버에서 온 데이터 (목록, 상세, 코드)        | TanStack Query (`features/*/queries.ts`) | 로딩·오류·재조회·캐시를 한 방식으로 처리            |
| 로그인 사용자, 로그인 여부                   | Zustand (`features/auth/store.ts`)       | 컴포넌트 밖(라우터, HTTP)에서도 읽어야 함           |
| 열린 탭 목록                                 | Zustand (`shared/screen/tabStore.ts`)    | 위와 같음                                           |
| 현재 보이는 탭                               | **URL** (저장하지 않음)                  | 주소가 곧 현재 화면. 새로고침·뒤로 가기와 항상 일치 |
| 액세스 토큰                                  | 메모리 (`shared/api/tokenStore.ts`)      | 브라우저 저장소에 남기지 않기 위해                  |
| 입력 중인 폼 값                              | React Hook Form (화면 안)                |                                                     |
| 화면 안에서만 쓰는 값 (선택한 행, 팝업 열림) | `useState` (화면 안)                     |                                                     |

서버 데이터를 Zustand 나 `useState` 로 복사해 두지 않습니다. 복사본은 원본과 어긋나기 시작합니다.

## 3. 탭 (MDI)

- 탭 하나 = 주소 하나 = 화면 하나입니다. 메뉴를 누르면 그 주소로 이동하고, 주소가 바뀔 때마다
  `app/router/syncTabs.ts` 가 탭 목록에 추가합니다. 주소 직접 입력, 뒤로/앞으로 가기도 같은 경로를 거칩니다.
- 열린 탭의 화면은 모두 그려 둔 채 현재 탭만 보이게 합니다 (`shared/ui/KeepAlive.tsx`).
  그래서 탭을 오가도 조회조건, 그리드의 스크롤·선택, 입력 중인 값이 그대로이고 다시 조회하지도 않습니다.
- 탭에서 마우스 오른쪽 버튼: 새로고침(화면을 처음 상태로) / 닫기 / 다른 탭 닫기 / 전체 닫기.
- 탭 수 상한은 `shared/config/constants.ts` 의 `MAX_TABS` 입니다.

### 화면을 만들 때 알아야 할 것

숨겨진 탭도 **살아 있습니다.** 그래서 다음을 지킵니다.

- 주기적으로 도는 작업(타이머, 자동 재조회)은 `useScreen().active` 가 `true` 일 때만 돌립니다.
- 팝업은 `shared/ui/Modal` 을 씁니다. 탭이 숨겨지면 팝업도 함께 숨고, 돌아오면 입력하던 내용 그대로 다시 나타납니다.
- 화면 정보는 `useScreen()` 으로 읽습니다: 제목, 메뉴 경로, 경로 변수(`params`), 권한(`can`).

### 왜 `<Activity>` 가 아닌가

React 19.2 의 `<Activity>` 는 숨길 때 effect 와 ref 를 정리합니다. AG Grid 36.3 은 이때 그리드를 파괴해서,
탭으로 돌아오면 스크롤·선택이 사라지고 그리드가 빈 채로 다시 만들어집니다 (브라우저에서 확인).
그래서 언마운트 없이 CSS 로만 숨깁니다. 숨기는 방식은 `KeepAlive` 한 곳에만 있으므로 나중에 바꾸기 쉽습니다.

## 4. 인증

```
로그인        POST /auth/login    → 액세스 토큰(본문) + 리프레시 토큰(httpOnly 쿠키)
API 호출      Authorization: Bearer <액세스 토큰>
토큰 만료     401 → POST /auth/refresh (쿠키 자동 전송) → 새 토큰으로 원래 요청 재시도
세션 만료     재발급도 401 → 화면 상태 정리 → 로그인 화면 (만료 안내 표시)
새로고침      메모리의 토큰이 사라짐 → 앱 시작 시 /auth/refresh 로 복원
```

- 이 흐름은 전부 `shared/api/http.ts` 안에 있습니다. 화면은 토큰을 다루지 않습니다.
- 동시에 여러 요청이 401 을 받아도 재발급은 한 번만 나갑니다.
- 로그인하지 않은 사용자는 `app/router/RequireAuth.tsx` 가 로그인 화면으로 보내고, 로그인 후 보던 주소로 돌려보냅니다.

### 권한

서버가 내려주는 메뉴(`GET /menus/my`)가 권한의 기준입니다.

- **메뉴에 없는 화면** → 주소로 직접 들어와도 "권한 없음" 화면이 나옵니다.
- **버튼 단위 권한** → 메뉴 항목의 `actions` (`READ` `CREATE` `UPDATE` `DELETE` `EXCEL`).
  화면에서는 `const { can } = useScreen()` 으로 읽어 `can('CREATE') && <Button>등록</Button>` 처럼 씁니다.

화면에서 버튼을 숨기는 것은 편의일 뿐입니다. **권한 검사는 반드시 서버에서도 합니다.**

## 5. 오류 처리

| 단계        | 하는 일                                                                                | 위치                                           |
| ----------- | -------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 변환        | 어떤 실패든 `ApiError` (`status`, `code`, `message`, `fieldErrors`, `traceId`) 로 바꿈 | `shared/api/ApiError.ts`                       |
| 알림        | 조회·저장 실패를 한 곳에서 알림. 4xx 는 토스트, 5xx·네트워크는 확인이 필요한 오류창    | `app/queryClient.ts` → `shared/ui/feedback.ts` |
| 입력란 표시 | 서버 검증 오류(`fieldErrors`)를 해당 입력란 아래에 표시                                | 화면에서 `applyFieldErrors(error, setError)`   |
| 화면 오류   | 화면을 그리다 난 오류는 그 탭 안에서만 안내 화면으로 바꿈                              | `shared/ui/ErrorBoundary.tsx`                  |

화면에서는 **실패 알림을 위한 try/catch 를 쓰지 않습니다.** 공통 처리가 이미 알립니다.
공통 알림을 끄고 화면에서 직접 처리하려면 조회·저장 옵션에 `meta: { silentError: true }` 를 줍니다.

## 6. 설정: 빌드 시점과 런타임

|             | 빌드 시점 (`.env`)                        | 런타임 (`public/config.js`)                 |
| ----------- | ----------------------------------------- | ------------------------------------------- |
| 정해지는 때 | `npm run build` 할 때 번들에 고정         | 브라우저가 페이지를 열 때                   |
| 바꾸려면    | 다시 빌드                                 | 서버의 `config.js` 파일만 교체              |
| 담는 값     | 배포 경로(`VITE_BASE_PATH`), 목 포함 여부 | API 주소, 환경 이름, 시스템 이름, 제한 시간 |

한 번 빌드한 산출물을 개발·검증·운영 서버에 그대로 올리고, 서버마다 `config.js` 만 다르게 둡니다.
`config.js` 의 형식은 `shared/config/runtimeConfig.ts` 가 검사하고, 잘못됐으면 앱 대신 원인을 화면에 보여줍니다.

## 7. 목 API

- `src/mocks/handlers` 가 서버 역할을 합니다. 브라우저(개발·시연)와 테스트가 같은 핸들러를 씁니다.
- 데이터는 메모리에만 있고 새로고침하면 처음 상태로 돌아갑니다.
- 운영 빌드에는 목 코드와 워커 파일이 들어가지 않습니다 (`VITE_ENABLE_MOCK` 이 `true` 일 때만 포함).
- 만료 상황 재현: 브라우저 콘솔에서 `__mock.expireAccessToken()` (토큰만 만료 → 자동 재발급),
  `__mock.expireSession()` (세션 만료 → 로그인 화면).
