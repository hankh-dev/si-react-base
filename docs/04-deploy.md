# 빌드와 배포

## 1. 빌드

```bash
npm ci
npm run verify     # 타입 체크 + 린트 + 서식 검사 + 테스트 + 빌드
```

산출물은 `dist/` 폴더입니다. 정적 파일뿐이므로 Node.js 없이 웹서버(Nginx, Apache)나 WAS 의 정적 경로에 올리면 됩니다.

```
dist/
  index.html       진입 페이지 (캐시하지 않음)
  config.js        런타임 환경설정 (캐시하지 않음, 환경마다 교체)
  favicon.svg
  assets/          화면·라이브러리 파일. 이름에 내용 해시가 붙어 있어 오래 캐시해도 됨
```

## 2. 환경별 설정

**한 번 빌드한 `dist` 를 모든 환경에 그대로 올립니다.** 환경마다 다른 값은 `config.js` 에만 있습니다.

1. `dist` 를 서버에 올립니다.
2. `deploy/config.<환경>.js` 를 `config.js` 라는 이름으로 덮어씁니다.

| 항목               | 설명                                                                |
| ------------------ | ------------------------------------------------------------------- |
| `envName`          | `local` `dev` `stg` `prod`. 운영이 아니면 상단에 환경 이름이 표시됨 |
| `appTitle`         | 브라우저 탭 제목, 상단 시스템 이름                                  |
| `apiBaseUrl`       | API 기본 경로. 같은 도메인의 리버스 프록시면 `/api`                 |
| `requestTimeoutMs` | API 제한 시간(ms)                                                   |

값이 빠지거나 형식이 틀리면 앱 대신 "환경설정 오류" 화면이 뜨고 어떤 항목이 문제인지 표시됩니다.
항목을 추가할 때는 `src/shared/config/runtimeConfig.ts`, `public/config.js`, `deploy/config.*.js` 를 함께 고칩니다.

## 3. 하위 경로에 배포

`https://host/portal/` 처럼 루트가 아닌 경로에 올릴 때:

1. `.env` 의 `VITE_BASE_PATH=/portal/` 로 바꾸고 빌드합니다. (배포 경로는 빌드할 때 정해집니다)
2. `dist` 내용을 웹서버의 `/portal/` 에 올립니다.
3. 웹서버의 "없는 주소는 index.html" 설정을 `/portal/` 기준으로 맞춥니다 (`deploy/nginx.conf.sample` 맨 아래).

## 4. 웹서버 설정

`deploy/nginx.conf.sample` 에 주석과 함께 있습니다. 어떤 웹서버든 아래 네 가지가 필요합니다.

| 필요한 것                                  | 이유                                                      |
| ------------------------------------------ | --------------------------------------------------------- |
| 없는 주소는 `index.html` 을 돌려줌         | `/system/users` 로 직접 들어오거나 새로고침할 때 404 방지 |
| `index.html`, `config.js` 는 캐시하지 않음 | 새 배포와 설정 변경이 바로 반영되도록                     |
| `assets/` 는 오래 캐시                     | 파일 이름이 내용에 따라 바뀌므로 안전하고, 화면이 빨라짐  |
| `/api` 를 백엔드로 넘김 (리버스 프록시)    | 화면과 API 를 같은 도메인으로 묶어 CORS·쿠키 문제를 없앰  |

배포 직후 이미 화면을 열어 둔 사용자는, 새 화면을 열 때 이전 버전의 파일을 찾지 못할 수 있습니다.
이때는 "새 버전이 배포되었습니다. 새로고침해 주세요" 안내가 나옵니다 (`shared/ui/ErrorBoundary.tsx`).

## 5. 폐쇄망

| 항목            | 상태                                                                         |
| --------------- | ---------------------------------------------------------------------------- |
| 외부 CDN 요청   | 없음. 글꼴은 사용자 PC 의 시스템 글꼴, 아이콘은 번들에 포함                  |
| 의존성 설치     | `npm ci` — `package-lock.json` 과 정확히 같은 버전을 설치                    |
| 사설 레지스트리 | `.npmrc` 의 `registry=` 주석을 풀고 주소를 바꿈 (Nexus 등)                   |
| 버전 고정       | `package.json` 에 범위(`^`) 없이 정확한 버전 (`.npmrc` 의 `save-exact=true`) |
| Node 버전       | 22.22 이상. 맞지 않으면 설치가 중단됨 (`engine-strict=true`)                 |

고객사 지정 글꼴이 있으면 npm 패키지나 `src/assets` 에 넣고 `shared/config/theme.ts` 의 `FONT_FAMILY` 와
`app/styles/global.css` 맨 앞에 추가합니다. 외부 주소로 불러오지 않습니다.

## 6. 보안 점검 대비

| 점검 항목               | 이 템플릿의 상태                                                            |
| ----------------------- | --------------------------------------------------------------------------- |
| 소스맵 노출             | 운영 빌드에 포함하지 않음 (`vite.config.ts` 의 `build.sourcemap: false`)    |
| 테스트용 코드·계정 노출 | 운영 빌드에 목 코드와 워커 파일이 들어가지 않음                             |
| 토큰 저장 위치          | 액세스 토큰은 메모리, 리프레시 토큰은 httpOnly 쿠키. 브라우저 저장소 미사용 |
| 콘솔 출력               | `console.log` 는 린트 경고. `console.warn/error` 만 허용                    |
| 스크립트 삽입(XSS)      | `dangerouslySetInnerHTML` 미사용. 서버 값을 HTML 로 넣어야 하면 반드시 소독 |
| 권한 우회               | 화면의 버튼 숨김은 편의. **서버에서 반드시 다시 검사**                      |
| 취약한 의존성           | `npm audit` 결과 0건 (작성 시점)                                            |

오픈소스 라이선스 목록 (배포 산출물에 들어가는 의존성만, 추가 설치 없이 동작):

```bash
npm run licenses            # 라이선스별 개수 요약
npm run licenses -- --csv   # 패키지별 목록 (이름, 버전, 라이선스)
```

작성 시점 기준 118개 패키지가 모두 MIT 입니다.

빌드 후 스스로 확인하는 방법:

```bash
npm run build
ls dist                       # mockServiceWorker.js 가 없어야 함
find dist -name "*.map"       # 아무것도 나오지 않아야 함
```
